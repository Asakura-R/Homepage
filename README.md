# 飲み物堂

エッセイ中心の個人サイト。Next.js（App Router）+ microCMS + Vercel。

## はじめかた

```bash
npm install
cp .env.example .env.local   # 中身を埋める
npm run dev
```

## 環境変数

```
MICROCMS_SERVICE_DOMAIN=xxxxxxxx
MICROCMS_API_KEY=xxxxxxxxxxxxxxxx
```

Vercel にも同じ2つを登録します。`NEXT_PUBLIC_` は付けないでください。付けるとAPIキーがブラウザから読めてしまいます。

## microCMS 側で必要な作業

既存のスキーマに合わせてありますが、**2点だけ設定が必要**です。

### 1. articles にカテゴリを追加（必須）

現在 `articles` にカテゴリのフィールドがありません。記事ごとに色を出し分ける仕組みがこれに依存しているので、追加してください。

| フィールドID | 種類 | 参照先 |
|---|---|---|
| `category` | コンテンツ参照 | categories |

複数選択はオフ（単一参照）にしてください。

### 2. categories の color に選択肢を登録（必須）

`color`（セレクトフィールド）の選択肢に、次の7つを**この文字列のまま**登録します。日本語や色コードではありません。

```
green
olive
amber
orange
red
magenta
blue
```

実際の色は `lib/format.ts` の `PALETTE` が持っています。

| 値 | 色 | 系統 |
|---|---|---|
| `green` | `#2C6A1E` | 緑 |
| `olive` | `#6E6008` | 黄土 |
| `amber` | `#96650A` | 山吹 |
| `orange` | `#A34A0C` | 橙 |
| `red` | `#A82420` | 赤 |
| `magenta` | `#912A62` | 臙脂 |
| `blue` | `#2A4C96` | 青 |

ティール `#04756B` はリンクやボタンなどの機能色なので、カテゴリには入れていません。

カテゴリが4つなら `green` / `amber` / `red` / `blue` のように離して選ぶと見分けやすくなります。

## 使っているフィールド

### articles

| フィールドID | 使い道 |
|---|---|
| `title` | タイトル |
| `content` | 本文。`.prose` のスタイルが当たる |
| `blocks` | 分岐などを含む記事用（後述）。`content` の後ろに表示される |
| `excerpt` | 一覧の抜粋。**空なら本文の冒頭120字を自動で使う**ので、書かなくてよい |
| `publishedAt` | 並び順と日付表示。空なら作成日で代用 |
| `limited` | ONにすると一覧に出ず、検索避けも付く。URLを知っている人だけ読める |
| `category` | ← 要追加 |

### categories

| フィールドID | 使い道 |
|---|---|
| `name` | 表示名 |
| `slug` | URL。`/category/nichijo` のようになる |
| `color` | ← 選択肢の登録が必要 |

### lives（イベント情報）

| フィールドID | 使い道 |
|---|---|
| `title` | タイトル |
| `date` | 並び順と、今後／過去の振り分け |
| `venue` `openTime` `startTime` | 「会場名／開場 19:00　開演 19:30」の形にまとめて表示 |
| `ticketUrl` | 「予約する」リンク。空なら出ない |
| `note` | 備考 |
| `isPublished` | **ONのものだけ表示される。** OFFのままだと出ないので注意 |

### settings

サイト名・紹介・SNS・画像はここから読みます。コードを触らずに変更できます。

| フィールドID | 使い道 |
|---|---|
| `siteName` | ヘッダー、フッター、ページタイトル |
| `siteDescription` | メタdescription、ABOUTページ |
| `artistName` `artistNameEn` | サイドバーとABOUT |
| `artistLabel` | サイドバーの一行紹介 |
| `twitterUrl` `instagramUrl` | SNSリンク。空欄なら表示されない |
| `ogImage` | SNS共有画像。未設定なら `/public/ogp.png` |
| `profileImage` | 宣材写真。未設定なら `/public/avatar.png` |

### profile

ABOUTページの中身です。

| フィールドID | 使い道 |
|---|---|
| `catchphrase` | 名前の横に、ティールの罫を添えて大きめに表示 |
| `introduction` | 自己紹介文。リッチエディタなので見出しや強調もそのまま反映される |
| `biograpy` | 経歴。繰り返しフィールド。年と内容の2列で並ぶ |

`biograpy` の中のカスタムフィールドは、フィールドIDが `year` / `event` のような一般的な名前であれば自動で認識します。認識できない場合は、その項目の文字列を上から順に「年」「内容」として扱います。意図通りに出ないときは `lib/format.ts` の `YEAR_KEYS` と `BODY_KEYS` に実際のフィールドIDを足してください。

## 分岐（読者の選択で展開が変わる文章）

### microCMS の設定（初回だけ）

**1. カスタムフィールドを2つ作る**

articles の画面右上「カスタムフィールド」から作成します。

| カスタムフィールドID | 表示名 | 中のフィールド |
|---|---|---|
| `textBlock` | 本文 | `body`（リッチエディタ） |
| `branchBlock` | 分岐 | `script`（テキストエリア） |

**2. articles に繰り返しフィールドを追加する**

| フィールドID | 種類 | 使うカスタムフィールド |
|---|---|---|
| `blocks` | 繰り返し | `textBlock` と `branchBlock` の両方 |

既存の `content` はそのまま残してください。過去の記事は `content` だけで今まで通り表示されます。

`textBlock` の `body` でも文字サイズのカスタムclass（`text-l` など）を使いたい場合は、こちらのフィールドにも同じclass名を登録してください。

### 表示される順番

1. `content`（従来の本文）
2. `blocks` を上から順に

分岐の前後に文章を置きたいときは、`content` を空にして `blocks` に「本文 → 分岐 → 本文」と積むか、`content` に前置きを書いて `blocks` に分岐だけ入れます。

### 分岐の書き方

`branchBlock` の `script` に、次のように書きます。

```
# はじまり
鞄を受け取ったら、妙に重い。
強盗は中身を確かめるべきか迷っている。
-> 中身を聞く : 聞く
-> 黙って持ち上げる : 持つ

# 聞く
「力士です」と言われた。
> 重いとは言えさすがに力士ではないか？
-> 米かと聞き返す : 米

# 持つ
持ち上がった。
-> いや、米かもしれない : 米

# 米
米だった。今は高いので、怒るに怒れない。
```

**分岐の仕組み**

| 書き方 | 意味 |
|---|---|
| `# 名前` | 場面の始まり（`#` は1つ）。**最初に書いた場面から読み始める** |
| `-> 表示する文 : 行き先の名前` | 選択肢 |
| 選択肢のない場面 | 結末。「最初から読む」ボタンが出る |

**場面の中で使える書き方**（Markdownとほぼ同じ）

| 書き方 | 表示 |
|---|---|
| 空行 | 段落の区切り |
| 改行 | そのまま改行 |
| `**太字**` | 太字 |
| `*斜体*` | 斜体 |
| `[文字](URL)` | リンク。`https://` か `/` で始まるURLのみ。外部サイトは新しいタブで開く |
| `![説明](画像のURL)` | 画像（1行に単独で書く）。`![説明](URL "キャプション")` で下にキャプション |
| `## 見出し` / `### 小見出し` | 見出し（`#` を2つ以上。**`#` 1つは場面の名前**） |
| `---` | 水平線 |
| `- 項目` / `1. 項目` | 箇条書き / 番号付き |
| `> 文` | 引用 |
| `{大:文字}` | 文字サイズ。`極小` `小` `大` `特大` `超特大` の5段階 |
| `\*` | 記号をそのまま表示したいときは前に `\` |

組み合わせもできます（`**{大:強調して大きく}**`、`[**太字のリンク**](/about)` など）。選択肢の表示文にも太字や文字サイズが使えます（リンクは文字だけになります）。

画像は microCMS の「メディア」にアップロードし、そのURLを貼ってください。閉じ忘れた記号は記号のまま表示されるので、画面が崩れることはありません。

全角の `＃` `→` `：` `＞` でも書けます。場面の名前は日本語でかまいません。

**書き間違いは下書きプレビュー（`/preview`）で確認できます。** 行き先の場面が見つからない、同じ名前の場面が2つある、どこからもたどり着けない場面がある、使えないリンク先や画像のURL、認識できない文字サイズの指定、といった問題を、プレビュー画面の分岐の上に赤枠で表示します。公開ページには表示されません。行き先が壊れた選択肢は、読者には出さないようになっています。

### フラグ（インタラクティブフィクションとして遊ぶ）

読者の選んだことを覚えておき、あとの場面の文章や選択肢を変えられます。フラグはすべて数として持ち、ON は 1、OFF は 0 です。一度も設定していないフラグは 0（OFF）として扱います。

```
# はじまり
[所持金 = 1000]
鞄を受け取ったら、妙に重い。財布には{=所持金}円。
-> 中身を聞く : 聞く [set 聞いた]
-> 黙って持ち上げる : 持つ [力 +1]

# 聞く
「力士です」と言われた。
-> 米かと聞き返す : 米
-> 千円で買い取る : 米 [所持金 -1000] [lock 所持金 >= 1000 "お金が足りない"]
-> 「米ですね？」と当てる : 米 [if 力 >= 1]

# 持つ
持ち上がった。思ったより、持てる。
-> やはり中身を聞く : 聞く

# 米
[if 聞いた] 力士ではなかった。
[if !聞いた] 聞かなくても、米だった。
残りは{=所持金}円。
```

**フラグを変える**（選択肢の行末に書くと、選んだとき／場面の中に単独で書くと、その場面に来たとき）

| 書き方 | 意味 |
|---|---|
| `[set 鍵]` | 鍵を ON にする |
| `[unset 鍵]` | 鍵を OFF にする |
| `[好感度 +1]` / `[所持金 -500]` | 増やす / 減らす |
| `[所持金 = 1000]` | その値にする |

**条件**

| 書き方 | 意味 |
|---|---|
| `[if 鍵]` / `[if !鍵]` | 鍵が ON のとき / OFF のとき |
| `[if 好感度 >= 3]` | 比較。`>=` `<=` `>` `<` `==` `!=` |
| `[if 鍵 and 好感度 >= 3]` | 両方満たすとき（`かつ` でも可） |
| `[if 鍵 or 地図]` | どちらかを満たすとき（`または` でも可） |

**どこに書くか**

| 置き場所 | 動き |
|---|---|
| 選択肢の行末に `[if 条件]` | 条件に合うときだけ出る。合わなければ**隠れる** |
| 選択肢の行末に `[lock 条件 "理由"]` | 条件に合わなければ**押せない状態で見せる**。`"理由"` は省略可 |
| 場面の中の行頭に `[if 条件]` | その行は条件に合うときだけ出る |
| `- [if 条件] 項目` / `> [if 条件] 文` | 箇条書きの項目・引用の行ごとに出し分け |
| 文中に `{=所持金}` | フラグの今の値を表示（1,000 のように桁区切り） |

- 場面の中は上から順に処理します。場面の途中に `[好感度 +1]` を置くと、それより下の行は変更後の値で判定・表示されます
- `[if 鍵] [好感度 +1]` のように並べると、「鍵が ON のときだけ好感度を増やす」になります
- 1つの選択肢に `[if …]` や `[lock …]` を複数書くと、すべて満たしたときだけ出る／押せるになります
- 条件で選択肢がすべて隠れた場面は、結末として扱います。すべて押せない状態になった場合は、「最初から読む」「ひとつ前に戻る」を出します
- 「ひとつ前に戻る」で戻ると、フラグも選ぶ前の状態に戻ります。「最初から読む」ですべて 0 に戻ります
- フラグはページを開いている間だけ覚えています。再読み込みすると最初からになります
- 全角の `＋` `－` `＝` `＞` `＜` `！` や全角数字でも書けます。フラグの名前に空白は使えません

**下書きプレビューでは**、分岐の下にいまの場面の名前とフラグの値が表示されます（公開ページには出ません）。また、どこでも変更していないのに条件や `{=…}` で使っているフラグがあると「名前の書き間違いかもしれません」と警告します（`[if 健]` と書いて、`[set 鍵]` のつもりだった、など）。

`[` `]` で囲んでいても、`[注]` のように命令として読めないものは文章としてそのまま表示されます。`if` `lock` `set` `unset` で始まるのに読み取れないものは、書き間違いとしてプレビューで知らせます。

### 読者から見た動き

選んだ場面は消えずに残り、選んだ選択肢が小さく記録されて、その下に次の場面が続きます。読み終えたあとに、自分がたどった道筋を読み返せます。各場面で「ひとつ前に戻る」、結末で「最初から読む」が使えます。

関係するファイルは `lib/branch.ts`（書き方の読み取りと場面の進行）、`lib/branchInline.ts`（文中の記号の読み取り）、`lib/branchLogic.ts`（フラグと条件）、`components/BranchStory.tsx`（表示と操作）、`components/ArticleBody.tsx`（本文と分岐の並べ方）、`app/globals.css` の「分岐」の節です。

## 下書きプレビュー

microCMS の **API設定 → 画面プレビュー** に、次のURLを登録します（articles のAPIで設定）。

```
https://nomimonodo.vendies.net/preview?contentId={CONTENT_ID}&draftKey={DRAFT_KEY}
```

`{CONTENT_ID}` と `{DRAFT_KEY}` はそのまま書きます。microCMS がプレビュー時に実際の値に置き換えます。

記事の編集画面で「画面プレビュー」を押すと、下書きの状態がサイトと同じ見た目で表示されます。

- 一度も公開していない記事も確認できる
- 上部に「下書きプレビュー」の帯が出る
- 分岐の書き間違いが赤枠で表示される
- 分岐の下に、いまの場面の名前とフラグの値が表示される
- 毎回その場で組み立てるので、保存し直してから再読み込みすれば最新の下書きが出る
- 検索エンジンには載らない。下書きキーがないと中身は取得できない

以前の形式（`/miscellany/{CONTENT_ID}?draftKey={DRAFT_KEY}`）が登録されたままでも、自動で `/preview` に転送されるので動きます。

**なぜ専用ページなのか。** 公開記事のページは表示を速くするため事前に作って保存しています。その仕組みの上でURLの `?draftKey=…` を読もうとすると、Vercel上ではそれが届かず、下書きが表示されなかったり、空のページが保存されたりします。プレビューだけを毎回組み立てる別ページに分けることで、公開ページの速さを保ったまま確実に下書きを見られるようにしています。

## 設計メモ

**色は役割で分けています。** ティール `#04756B` はリンク・ボタン・導線といった「機能」だけに使い、記事の分類には7色のカテゴリ色を使います。リンクの色が記事ごとに変わらないので読者が迷いません。

**無限スクロールは2回で止まります。** そのあとは「もっと読む」ボタンに切り替わります。無制限に自動読み込みすると、下部のプロフィールやフッターに永久に到達できなくなるためです。回数は `components/ArticleList.tsx` の `AUTO_LOAD_LIMIT` で変えられます。

**本文の見た目は `.prose` にまとまっています。** microCMS が吐き出す `<h2>` や `<blockquote>` にスタイルを当てているので、記事を書くときに装飾を意識する必要はありません。

**表とリンク羅列だけ、CSSでは届かないので加工しています。** `lib/format.ts` の `enhanceBody` が、表を横スクロール用の枠で包み、リンクだけの段落に `link-row` クラスを付けます。強盗記事の「Amazon Yahooショッピング ヨドバシ」のような並びが対象です。

**取得系はすべて try で囲んであります。** カテゴリやイベントが0件でもビルドは通り、その部分だけ表示されません。失敗時は `console.error` にログが出るので、Vercelのログで原因を追えます。

## アクセス解析

Vercel Analytics と Speed Insights を入れてあります。どちらも Cookie を使わないので、同意バナーやプライバシーポリシーの追加対応は不要です。

**Vercel のダッシュボードで有効化が必要です。** プロジェクトの Analytics タブと Speed Insights タブをそれぞれ開き、Enable を押してください。コード側は導入済みなので、それだけで計測が始まります。

無料枠は月2,500イベントまでです。足りなくなったら Cloudflare Web Analytics（無料・無制限・Cookieなし）への乗り換えを検討してください。

計測を止めたい場合は `app/layout.tsx` の `<Analytics />` と `<SpeedInsights />` を消します。

## Vercel の設定

Framework Preset は **Next.js**。以前 Astro だった場合は変更が必要です。Output Directory の Override は外してください（Next.js の出力先は `.next` です）。
